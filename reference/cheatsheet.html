Midterm cheat sheet

Every formula, recipe and rule list from Lessons 1–13 on one page. Read it the morning of the exam.

Big picture L1 · Ch 2

  • Three easy pieces: virtualization (CPU and memory), concurrency, persistence
  • Mechanism = how (context switch). Policy = which (scheduler).
  • Threads share code, heap, globals and open files; each has its own stack, registers and PC
  • counter++ = LOAD → ADD → STORE. Each thread has its own register, and memory changes only on STORE.
  • OS goals: abstraction, performance, protection, reliability (also energy, security, mobility)

The process L2 · Ch 4

  • Machine state = memory (code, data, heap, stack) + registers (PC = address of the next instruction; SP = top of stack: locals, params, return addresses) + I/O (open files)
  • Creation: load code + static data (lazily) → stack (argc/argv) → heap → fds 0/1/2 → jump to main
  • Running ⇄ Ready (scheduled/descheduled); Running → Blocked (I/O starts); Blocked → Ready (I/O done). Never Blocked → Running.

fork / exec / wait L3 · Ch 5

  • fork() returns 0 in the child, the child's PID in the parent, −1 on error. The child resumes after the fork.
  • n forks in a row (or in a loop) → 2ⁿ processes. A printf inside the loop runs 2ⁿ⁺¹ − 2 times.
  • if (fork()==0) fork(); → 3 processes, including a grandchild
  • Recipe: draw the tree, then follow each process's own return value
  • exec() replaces the program; same PID; never returns on success. fork makes a new PID.
  • wait() only works on your own children; otherwise it returns −1 (ECHILD). It also reaps zombies.
  • Output order is nondeterministic unless the parent calls wait()
  • Redirection: in the child, close(1); open(file) (the file gets fd 1), then exec
  • <unistd.h> = POSIX API (fork, exec, getpid, read, write, close); <sys/wait.h> = wait
  • Makefile: target: deps, then a TAB before the command; all: first; run: all

Limited direct execution L4 · Ch 6

  • Boot (kernel mode): the OS sets up the trap table and starts the timer (both privileged)
  • Trap: hardware saves registers to the kernel stack → switches to kernel mode → jumps to the handler
  • Return-from-trap: restores registers → switches to user mode → jumps to the user PC
  • Cooperative: the OS only regains control on a syscall, yield or a fault, so an infinite loop means rebooting
  • while(1); answer: timer interrupt → hardware saves registers and enters kernel mode → handler → scheduler → context switch → return-from-trap into another process
  • Two saves: (1) the hardware saves user registers onto the kernel stack (on every interrupt); (2) switch(): the OS saves kernel registers into the proc struct

Scheduling basics L5 · Ch 7

Turnaround = completion − arrival Response = first run − arrival average = sum ÷ n
  • FIFO: arrival order; non-preemptive; convoy effect
  • SJF: shortest burst first; non-preemptive; optimal turnaround if all jobs arrive together
  • STCF: least remaining time; re-decides at every arrival; preemptive
  • RR: one time slice each; best response time, worst turnaround
  • Identify the policy: a job split into pieces means preemption. Test FIFO (earliest arrival each time), SJF (shortest waiting job each time) and STCF (no newcomer shorter than the running job's remaining time), and list every policy that fits.
  • Gantt charts with 1-indexed slots: a job in slots 1–3 completes at 3
  • Time-slice overhead = switch ÷ (slice + switch)

MLFQ: the 5 rules L6 · Ch 8

  1. If Priority(A) > Priority(B), A runs (B doesn't).
  2. If Priority(A) = Priority(B), A & B run in RR.
  3. When a job enters the system, it is placed at the highest priority.
  4. Once a job uses up its time allotment at a given level (regardless of how many times it has given up the CPU), its priority is reduced.
  5. After some time period S, move all the jobs in the system to the topmost queue.
  • Starvation and changing behaviour are fixed by R5. Gaming the scheduler is fixed by R4.
  • Trace: one lane per queue; using a full slice drops a job one level; lower queues run only when all higher ones are empty; after a boost, a job walks down the levels again

Lottery & stride L7 · Ch 9

  • Winning ranges are consecutive blocks in list order. Use 1-based ranges if the question says "1 to total", otherwise 0-based.
  • Fair only over many draws. A finished job leaves with its tickets, so short jobs run exactly their burst count.
  • Currency: global = local ÷ user's local total × user's global tickets
stride = BIG ÷ tickets run the job with the lowest pass; pass += stride ties → the job listed first
  • A new job joining at pass 0 hogs the CPU. Lottery needs no global state; stride is exact.

Multiprocessor L9 · Ch 10

  • SQMS (single queue): simple and balanced, but has ✗ lock contention (doesn't scale) and ✗ poor cache affinity
  • MQMS (a queue per CPU): fixes both problems (no shared lock, jobs stay put), but suffers ✗ load imbalance
  • Fixes: migration and work stealing (a less-busy queue peeks at a fuller one)
  • Drawing: without balancing, each CPU round-robins its own queue; with balancing, even out the job counts (moving jobs as needed)
  • Coherence: bus snooping. You still need locks for shared queues.

Address spaces & malloc L10–11 · Ch 13–14

  • Code at the top (0 KB), then heap growing ↓, free space, and stack growing ↑ from the end
  • Goals: transparency, efficiency, protection
  • p = heap address · &p = address of the pointer variable (stack) · *p = the value in the heap
  • malloc(n*sizeof(int)); strings need strlen(s)+1; calloc zeroes the memory
  • tmp = realloc(p, new); if (tmp) p = tmp; then free(p); p = NULL;
  • Dangling / use-after-free: the pointer still holds the freed address. It "works" because the memory isn't erased, and the next malloc may reuse the same block. This is UB.
  • Double free is a run-time error: the compiler can't track it, and the allocator's metadata usually calls abort
  • Leaks, uninitialized reads, overflow. Tools: valgrind, ASan.
  • malloc/free are library calls; underneath they use brk/sbrk and mmap

Base & bounds L12 · Ch 15

if 0 ≤ VA < bounds: PA = VA + base else: fault (exception → OS kills the process)
  • This is the default, where bounds = size. If bounds is a physical end address, check PA < bounds instead.
  • Hardware: privileged mode, base/bounds registers in the MMU, privileged instructions to set them, exceptions
  • OS: free list (allocate on create, reclaim on exit), save/restore base and bounds in the PCB on each context switch, exception handlers
  • Weakness: internal fragmentation (the unused heap–stack gap)

Segmentation L13 · Ch 16

segments = 2^(selector bits) max seg size = 2^(offset bits) seg = (VA & SEG_MASK) >> SEG_SHIFT offset = VA & OFFSET_MASK grows +: offset < size ? PA = base + offset grows −: neg = offset − max_seg_size |neg| ≤ size ? PA = base + neg
  • 14-bit example: SEG_MASK 0x3000, SEG_SHIFT 12, OFFSET_MASK 0xFFF
  • Why shift? After masking, the bits are still high up (e.g. 4096). Shifting gives a small index 0–3.
  • Usually 00 code, 01 heap, 11 stack. Use the table in the question (Bilal's slide table lists 10 for the stack).
  • 2¹⁰ = 1K, 2¹² = 4K, 2¹³ = 8K, 2¹⁴ = 16K, 2²⁰ = 1M, 2³⁰ = 1G
  • Protection bits (R/W/X): code can be shared. Problem: external fragmentation, fixed by compaction or best/worst/first-fit and buddy allocation.
