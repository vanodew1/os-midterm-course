Reference

Glossary

One tight definition per term. The lessons use these exact words. Avoid lists other names you may see for the same idea.

Processes & the CPU L2–4

Process
A running program: the program plus its machine state. Avoid: task, job
Machine state
Everything a running program can read or change: its address space, registers (PC, SP) and open files.
Program counter (PC)
The register holding the address of the next instruction to execute.
Stack pointer (SP)
The register pointing to the top of the stack, which holds parameters, local variables and return addresses.
Thread
One stream of execution inside a process. It shares the process's address space and files but has its own stack, registers and PC.
Ready / Blocked
Ready: able to run but not chosen yet (xv6 RUNNABLE). Blocked: can't run until an event such as I/O finishes (xv6 SLEEPING). Avoid: "waiting" (ambiguous)
PCB (process control block)
The per-process structure (xv6 struct proc) holding the PID, state, saved registers, memory info and open files. The process list is the collection of all PCBs.
Zombie
A child that has exited but hasn't yet been reaped by its parent's wait(). Avoid: orphan
Orphan
A child whose parent exited first. It is adopted (and later reaped) by init.
fork()
A system call that creates a near-copy child process. It returns 0 in the child, the child's PID in the parent, and −1 on failure.
exec()
Replaces the calling process's program. The PID stays the same, and it never returns on success.
wait()
Blocks the parent until one of its own children finishes, then reaps it.
Limited direct execution (LDE)
Running programs directly on the CPU, but limited by hardware modes and a timer so the OS keeps control.
User mode / kernel mode
Hardware privilege levels. User code can't run privileged instructions; the kernel can do anything.
Trap
An instruction that jumps into the kernel and raises the privilege level. The hardware saves registers to the kernel stack. Avoid: "interrupt" (that comes from a device)
Trap table
The table of handler addresses the OS installs at boot, with a privileged instruction.
Timer interrupt
A hardware interrupt every few ms that hands control back to the OS, even from a while(1) loop.
Context switch
Saving one process's registers into its PCB and restoring another's, so a return-from-trap resumes the new process. Avoid: "mode switch" (that's user ↔ kernel)

Scheduling L5–9

Turnaround time
Completion time − arrival time.
Response time
First-run time − arrival time.
Preemptive
Able to stop a running job before it finishes in order to run another one (STCF, RR, MLFQ).
Convoy effect
Short jobs stuck waiting behind a long one under FIFO.
STCF
Preemptive SJF: at every arrival, run the job with the least remaining time. Avoid: SRTF (same thing, not the slides' name)
Time slice (quantum)
How long RR runs a job before switching. It must be a multiple of the timer period.
MLFQ
Several priority queues; the highest non-empty queue always runs, and jobs move between queues based on how they use the CPU.
Time allotment
The total CPU time a job may use at one MLFQ level before it is demoted, however many times it gives up the CPU.
Priority boost
MLFQ Rule 5: every period S, all jobs move to the top queue.
Starvation
A runnable job never gets the CPU because higher-priority work never runs out. Avoid: deadlock
Gaming the scheduler
Giving up the CPU just before a slice ends in order to stay at high priority.
Proportional share
Scheduling that guarantees each job a percentage of the CPU instead of optimizing turnaround or response.
Ticket
A unit of share. A job's fraction of all tickets is its fraction of the CPU.
Stride / pass
Stride = BIG ÷ tickets. Pass is the job's running counter; the lowest pass runs next, then pass += stride.
vruntime
CFS's virtual runtime. It grows by runtime × 1024/weight, so high-weight tasks age more slowly.
Weight
A number derived from the nice value (nice 0 = 1024). A bigger weight means a bigger CPU share.
sched_latency / min_granularity
The window in which every runnable task runs once, and the floor on any task's slice.
min_vruntime
The smallest vruntime among runnable tasks. New and waking tasks are given it.
Cache affinity
A process runs faster on the CPU whose cache still holds its data.
SQMS / MQMS
Single-queue multiprocessor scheduling (one global queue) and multi-queue multiprocessor scheduling (one queue per CPU).
Load imbalance
Per-CPU queues holding unequal amounts of work, so shares are unfair or a CPU sits idle.
Migration / work stealing
Moving jobs between CPU queues. With work stealing, a less-busy queue takes jobs from a fuller one.

Memory L10–13

Address space
A process's private view of memory (code, heap, stack), starting at 0. Avoid: memory map
Virtual address (VA)
Any address a program sees. Hardware translates it to a physical address (PA). Avoid: logical address
Dangling pointer
A pointer that still holds the address of memory that has been freed.
Use-after-free
Reading or writing through a dangling pointer. It is undefined behaviour and can appear to work.
Double free
Calling free() twice on the same block. It is a run-time error (undefined behaviour), usually caught by the allocator.
Memory leak
Heap memory that is allocated and never freed.
Address translation
Hardware turning every VA into the PA where the data really lives.
MMU
The memory management unit: the part of the CPU that holds base/bounds (or segment registers) and translates and checks addresses.
Base and bounds (dynamic relocation)
PA = VA + base, valid only if VA < bounds (the size).
Free list
The OS's list of physical memory ranges that aren't in use.
Segment
A contiguous piece of the address space with one role (code, heap, stack) and its own base and bounds.
Negative offset
For the downward-growing stack: offset − max segment size, so PA = base + negative offset.
Internal fragmentation
Wasted space inside an allocation, such as the unused heap–stack gap under base and bounds.
External fragmentation
Free memory split into small holes between allocations, so a large request fails even though enough total space is free.
Compaction
Copying segments together, and updating their bases, to merge the free holes. It is expensive.
